# Security Policy

## Supported Versions

Security fixes are provided for the current production deployment of Jass Space.
Older revisions and forks are not supported unless explicitly stated otherwise.

## Reporting a Vulnerability

Please report suspected vulnerabilities privately through GitHub's **Report a
vulnerability** form for this repository:

https://github.com/JSM33T/JassisWebspace/security/advisories/new

Do not open a public issue for vulnerabilities involving authentication,
authorization, sensitive data, secrets, production infrastructure, or a
reproducible exploit.

Include enough information to investigate safely:

- A clear description of the issue and its potential impact.
- The affected component, endpoint, or configuration, and relevant version or
  commit details.
- Reproduction steps or a minimal proof of concept.
- Any suggested remediation or mitigation.
- Your preferred contact method for follow-up and credit.

Please avoid accessing, altering, or retaining other users' data; disrupting
the service; or publishing exploit details before a fix is available.

## Scope

This policy covers the first-party Jass Space application, repository-managed
GitHub Actions workflows, Docker Compose deployment configuration, and the
services operated from this repository.

Third-party services, dependencies, social engineering, and issues requiring
physical access are outside this repository's security-reporting scope. Please
report vulnerabilities in third-party software directly to the relevant vendor
or project.

## Response Process

We aim to acknowledge valid reports within seven days, assess impact and
remediation options, and keep reporters informed about material progress. Once
the issue is resolved, we will coordinate any public disclosure and credit
where appropriate.
